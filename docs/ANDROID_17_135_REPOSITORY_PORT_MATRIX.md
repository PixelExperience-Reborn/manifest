# PixelExperience-Reborn — аудит всех 135 репозиториев для AOSP 17

**Начат:** 2 ноября 2026 года. **Обновлён:** 4 ноября 2026 года. **Статус:** подтверждённая выборочная синхронизация P0 и аудит 135 проектов; полная сборка Android 17 ещё не выполнялась.

Источники: [организация PixelExperience-Reborn](https://github.com/PixelExperience-Reborn), [рабочий manifest PR #2](https://github.com/PixelExperience-Reborn/manifest/pull/2), [vendor_aosp PR #1](https://github.com/PixelExperience-Reborn/vendor_aosp/pull/1). Сопоставлены имена всех 135 действующих репозиториев с тремя XML-snippets на рабочей ветке manifest `port/a17-aosp17-manifest-20261102`, а также пути с AOSP `android-17.0.0_r1`.

## Подтверждённые результаты

- 135 уникальных GitHub-репозиториев, у каждого default branch `seventeen`.
- 135 уникальных PE-проектов: **64 в `pixel.xml`, 24 в `pixel-extras.xml`, 47 в `pixel-caf.xml`**.
- Каждый PE-проект сопоставлен с существующим репозиторием, нет лишних или недостающих форков.
- **55** проектов заменяют пути AOSP17; **80** добавляют собственные пути PE.
- В базовом manifest **1087** AOSP-проектов; **71** исключён через remove.xml (из них 55 заменены PE). Эффективный граф по путям: **1016 AOSP + 135 PE = 1151** без повторяющихся путей.
- ЭТО НЕ ТЕСТ `repo sync`, не проверка наличия всех refs/коммитов, не компиляция и не подтверждение совместимости Android 17.

## Что сделано и что блокирует базу

1. `build/make`: **официальный AOSP17 остаётся нетронутым** в проверочных профилях. Старый локальный кандидат с изменением `envsetup.sh` больше не требуется для подключения PE-команд: используются встроенный AOSP `source_vendorsetup()` и адаптированный `vendor_aosp/vendorsetup.sh`. Остальные изменения оригинального PE Build/Make по-прежнему требуют отдельных проверок.
2. `vendor/aosp`: черновой PR с Bash-командами PE, roomservice, версией, AVB/OTA preflight, bacon. Полная сборка не выполнена.
3. `build/soong`: ветка `port/a17-soong-dumpvars-20261103` основана на AOSP17; опубликованы PE build banner (`f67e76e`), очистка OTA SHA-256 sidecars (`cf78167`) и регрессионный Go-тест (`6215d41`). Полный Go/Soong bootstrap и Android17-сборка не выполнялись.
4. Остальные исходники `art`, `bionic`, frameworks, services, hardware и prebuilts не могут считаться адаптированными только по имени ветки.
5. `vendor/aosp`: доступ к отсутствующему проприетарному `vendor/gms/products/gms.mk` теперь явно зависит от `WITH_GMS=true` и проверяется на наличие; Google-only свойства, Gboard и SetupWizard также условны. Лицензионный источник GMS и полная проверка product.mk по-прежнему отсутствуют.
6. Qualcomm/NXP HAL необходимо проверять только для реально нужных sm8450/mondrian компонентов. Деревья иных телефонов в базу не включать.
7. Устаревшие GCC 4.9 и старые clang prebuilts нельзя включать в актуальную систему сборки автоматически.

Дополнительные результаты проверки P0: [решения по ART, Bionic и system/core](ANDROID_17_P0_SOURCE_DECISIONS.md).

## Изолированная основа для проверки AOSP 17

Созданы три проверочных профиля: [чистый AOSP17](../aosp17_reference.xml), [AOSP17 + PE Soong](../aosp17_pe_bootstrap.xml) и [AOSP17 + PE Soong + PE Vendor](../aosp17_pe_envsetup.xml). Официальный `repo` успешно разобрал все три графа (1068, 1068, 1069 default-selected проектов); исходные XML декларации содержат соответственно 1071/1071/1072 путей после 16 удалённых нерелевантных device-деревьев. Три Darwin-пакета с группой `notdefault` исключаются только из default selection, не удаляются. Исторические 135 PE-форков не подменяются и не удаляются. [Подробности](ANDROID_17_BOOTSTRAP_PROFILES.md).

**Текущий статус:** [19 выбранных P0-проектов успешно синхронизированы](https://github.com/PixelExperience-Reborn/manifest/actions/runs/41727970000) с точными SHA и host/source-проверками; 20 исторических P0 строк получили первоначальный аудит, включая официальный `prebuilts/build-tools` без собственного форка. P1 `system/vold`, `frameworks/opt/telephony` и `frameworks/opt/timezonepicker` импортированы, [совместная синхронизация 22 проектов](https://github.com/PixelExperience-Reborn/manifest/actions/runs/41742534953) **прошла**. Старый дополнительный `device/custom/sepolicy` прошёл лишь аудит и остаётся неактивным. Проверки сборки и устройства по-прежнему отсутствуют. Это НЕ полная синхронизация всех 1069 выбранных проектов, не запуск Soong/Make-компиляции, не готовая PixelExperience Android 17 и не испытание на mondrian.

**Проверенные нативные P0-профили:** [`aosp17_pe_p0_native.xml`](../aosp17_pe_p0_native.xml) закрепляет официальные исходные SHA для ART (`b753cf97923c`) и Bionic (`06356e41c5ed`). [`aosp17_pe_p0_core.xml`](../aosp17_pe_p0_core.xml) добавляет точное дерево AOSP17 `system/core`, воспроизведённое как отдельный GitHub snapshot `8e0f22aa` (tree SHA `332cc42d`, upstream SHA `545d2487`). CI с официальным `repo manifest` прошёл для обоих профилей: 1069 выбранных проектов. Добавлен также [`aosp17_pe_p0_frameworks.xml`](../aosp17_pe_p0_frameworks.xml), закрепляющий официальный `frameworks/native` AOSP17 без PE-патчей; профиль прошёл проверку через `repo manifest`. Это не компиляция и не тест на mondrian.

**Recovery P0:** [аудит и решения по историческим PE-изменениям](ANDROID_17_RECOVERY_PORT_AUDIT.md). [`aosp17_pe_p0_recovery.xml`](../aosp17_pe_p0_recovery.xml) добавляет ревьюированную ветку Recovery Android17 с закреплённым SHA `0ed8dc4` к предыдущему P0-графу. Отдельная CI проверяет host C++ stage-тесты и сохранение проверок подписи/SPL; официальная `repo` проверка этого manifest-профиля также пройдена. Ни одна из этих проверок не является полноценной сборкой или тестом на mondrian.

**Media P0:** [аудит PixelExperience Frameworks AV](ANDROID_17_FRAMEWORKS_AV_PORT_AUDIT.md). Профиль [`aosp17_pe_p0_av.xml`](../aosp17_pe_p0_av.xml) закрепляет портированные изменения Codec2 SHA `5db9a615` поверх чистой AOSP17 с ранее проверенными P0-компонентами. Текущие CI проверяют граф repo и наличие PE-дельты/Android gtests, **но сами C++ Android gtests не запускались**.

## Инварианты для всех 135 репозиториев

[Автоматическая проверка всех 135 форков](../tools/validate_135_repository_matrix.py) сверяет тройку исторических PE snippets с матрицей: **64 + 24 + 47 = 135** уникальных checkout-путей и GitHub-репозиториев. Отдельно фиксируются приоритеты **P0: 20, P1: 26, P2: 85, P3: 4**. [CI #41720489560](https://github.com/PixelExperience-Reborn/manifest/actions/runs/41720489560) прошёл. Проверка подтверждает только **полноту учёта**.

Каждый форк подлежит индивидуальному **аудиту**. Результат может быть: ревьюированная PE-дельта, сохранение неизменённого AOSP17, перенос зависимости в mondrian device/vendor, либо признание старого компонента ненужным. **Нельзя автоматически делать 135 фиктивных изменений** или подключать несовместимые Android14-деревья к AOSP17. Для подтверждения работоспособности необходима компиляция и испытания.

**Портирование деревьев mondrian:** существующая LineageOS 24.0 — актуальная самостоятельная база с полезными аппаратными реализациями. Для новой независимой PE-Reborn платформы допустим выборочный перенос совместимых конфигураций, исправлений и HAL-привязок с проверкой лицензий, зависимостей и AOSP17. См. [политику повторного использования и план нативного порта](ANDROID_17_MONDRIAN_LINEAGE_TO_NATIVE_PORT_POLICY.md). Нельзя ни импортировать всё вслепую, ни отвергать рабочие решения только из-за происхождения из LineageOS.

## Условия завершения каждого репозитория

Точное закрепление источника AOSP17 → сравнение истории и PE-патчей → отбор нужных изменений → ревью и проверка совместимости интерфейсов/зависимостей → локальные тесты/сборка → PR → проверка в целом дереве. Статус `seventeen` не заменяет ни одного из этих шагов.

## Очерёдность

- **P0:** стартуем с ядра платформы, ART, Bionic, Soong/Make, SELinux, frameworks, update engine и обязательных модулей.
- **P1:** PE-функции, Settings, услуги телефонии, providers и permission service.
- **P2:** внешние утилиты и аппаратура Qualcomm/NXP по необходимости, не все подряд.
- **P3:** устаревшие компиляторы и другие потенциально лишние prebuilts.
